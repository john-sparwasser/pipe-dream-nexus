One tool instead of six.

A SMW hack today stitches together a level editor, a block inserter, a sprite inserter, a music patcher, an ASM runner and an assembler, each with its own folders and its own way to break your ROM at 2am. Pipe Dream is the one program that does all of it: same window, same project, same undo history.

Share the project, not the ROM.

Your work saves to a .pdp project file: plain JSON describing every edit relative to a pinned base ROM. No ROM data at all.

  • Hand a collaborator the file; with the same base they see exactly what you see
  • It's text: commit it, branch it, diff it like any other file
  • The base ROM is read, never written; a bad session costs a rebuild
  • Builds are outputs, and ship as BPS patches

Easier to get started.

Most people who want to make a Mario level give up somewhere between the fifth download and the first hex offset. Pipe Dream is built so you never hit that point.

Nothing to assemble first

One install, one window. No tool chain to wire up before you can place a block.

Guided first run

It walks you through pointing at your base ROM and making a project, and recovers on its own when a base goes missing.

Plain language, not raw bytes

Level settings, exits and tile properties are named fields. You shouldn't need a hex table to change the music.

Undo everywhere

Real edit history, so poking at something you don't understand yet is how you learn instead of how you lose an afternoon.

What works today.

Everything Lunar Magic edits, edited here, plus the jobs you used to hand to separate tools.

Level editing

Objects and sprites on a live canvas: place, drag, rubber-band select, undo. Rendered through the real object engine, so what you see is what loads.

Map16 & graphics

Map16 pages with tile properties (acts-like, palette, priority, flips), ExGFX import, a GFX browser, palette grids, background picker.

Overworld

Areas, level tiles, events and transitions, with Lunar Magic's own overworld palettes so every colour edits.

Exits & entrances

Main entrance, secondary entrances, vanilla and LM secondary exits, listed and edited instead of hand-poked in hex.

Custom sprites

Import PIXI sprites, slot them, edit their config and place them like vanilla ones. Up to 255 sprites a level, with our own MIT driver.

Patches & BPS

A project keeps its Asar patches, applied in order at build, and the build ships as a BPS patch the way the community expects. Asar comes bundled.

Cross-platform

One codebase, no platform-specific editor code. Windows and Linux builds come out of CI on every commit; macOS builds from the same source.

Scriptable

The same executable runs headless for batch jobs and CI: render, diff, self-check, and creating or building projects.

Install.

No toolchain, no compiling. Windows gets a per-user installer needing no admin rights, and CI proves it works by installing it, running a self-check from the installed binary and uninstalling again. Linux gets a single self-contained executable: chmod +x and run. Either way it carries its own .NET runtime, so there's nothing to install alongside it, and the editor can update itself from then on.

Take the file for your platform from the latest release: the PipeDream-Setup installer for Windows, or PipeDream-linux-x64 for Linux.

Every commit also gets built and tested on both platforms, so if you want something newer than the last release, the build workflow has one, though those artifacts need a GitHub login and expire after 90 days, which is why the release above is the better link.

You supply your own copy of Super Mario World. Pipe Dream ships no game data.

Status.

Pipe Dream is pre-release and under active development. It now covers everything Lunar Magic edits; the latest release is v0.8.0. Try it on a copy of a hack rather than the hack, keep backups of any ROM you point it at, and file what breaks. What's next is on the roadmap.

It's MIT licensed and the whole thing is on GitHub. Bug reports from people who got stuck in the first ten minutes are the most useful kind. Come say hi and ask questions on the Discord.

Resources.

Super Mario World bank logs is the game's disassembly split by ROM bank and written up as browsable pages, in the style of Patrick Johnston's Super Metroid logs. Every routine has a plain-English name, a short summary, a list of what calls it, and a comment on each instruction. Jumps and named tables are links, hardware registers show their names on hover, and one search covers every bank. There is also a RAM map and an interactive call graph.

It builds on the community SMWDisC disassembly, and the names and comments were written with Claude and checked against the code. Where the guess was uncertain the comment says so, so treat it as a reading aid and not gospel. Corrections are welcome on the Discord.
